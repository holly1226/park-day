# 公园人流与设施模拟器 · v2

类型：交互式软件原型，延续既有像素场景、苔绿与奶油白配色。

目标用户：公共空间设计师、社区运营者及对公园使用感兴趣的人。

主路径：电脑当前时间进入 → 看见实际数量的小人和人流 → 切换时间与昼夜 → 布置设施 → 比较当前与初始布局 → 阅读 AVA 的筛选条件、公式、SQL 与结果表。

## 交互

- 默认读取用户电脑的本地小时和分钟，跟随时钟每 10 秒刷新；手动选择或播放后退出实时跟随，可随时返回。
- 支持全天 00:00–23:59；模拟记录以半小时为单位，界面显示当前时间与实际统计区间。
- 18:00–06:00 路灯亮；树影方向与长度、傍晚暖色、夜间蓝色叠层随时间变化。固定周期为演示，不是实际地理日照。
- 一位模拟访客绘制一个小人；停留者在设施旁，行走者沿步道与设施接近路径运动。支持暂停动画、减少动态效果偏好。
- 编辑模式可拖动、方向键微调；添加长椅、凉亭、饮水点、树木、路灯；调整容量；删除、撤销、重置。
- 边界、湖面、步道和设施间距有放置检查。最多 32 处设施。
- 当前布局自动存入本机 localStorage，可导入/导出 JSON。初始布局独立保留。

## 模拟与 AVA 的分工

模拟器用透明规则生成两个方案、两种天气、48 个半小时时段的记录。

全园人数由时段和天气决定，同一天气同一时段对两种布局保持相同人数，避免通过“凭空增加访客”制造改善。访客通过确定性随机数按容量平方根、到步道距离、遮阴、设施类型节律、夜间照明偏好选择目标；想停留的人如果目标满员，会继续行走并记为未能使用。

树木影响预设树冠投影内的遮阴；路灯在 165 地图单位内标记照明覆盖。模型不进行实际照度、气象、行为预测或经校准的因果推断。

每个时段包含设施行 `record_type=facility` 与一条全园行 `record_type=park`。全园人数是 walking+resting，停留人数等于设施 occupied 合计。全园 visits 是模拟入园人次；设施 visits 为可重复到访，二者不能直接混加。

AVA 真实执行 source/schema/semantic/query，驱动快照、总览、趋势、初始与当前方案比较以及五类分析。一次数据集替换与一批查询在同一队列内完成，防止编辑时读到其他布局。AVA 不负责生成访客行为。

每个分析显示：方案、天气、统计区间、记录数 → 三步自然语言解释 → 结果图 → 原始 SQL 和返回表。预设 SQL 无需密钥；本地可选 analyze 接收当前布局，避免自由问题使用旧数据。

## 验收

检查数量守恒、布局比较相同人数、遮阴与照明响应、真实 AVA 结果与模拟器一致。真实浏览器检查电脑时间、手选时间、昼夜、动画位移、拖动增删、JSON 导入与空布局、撤销与持久化、当前/初始切换、五类查询、证据与导出、手机与中等宽度、加载失败恢复。构建与 GitHub Pages 发布通过后检查线上。

## 界面与依赖

GSAP + @gsap/react 实现行走路径和入场动画，使用带作用域与销毁清理的 useGSAP、matchMedia 减少动态效果。React Bits ClickSpark 用于布置工具的点击反馈，保留原许可证至 public/licenses/react-bits.txt。taste-skill 已安装用于后续设计工作；本次保留既有交互应用结构，不套用商业展示站的整屏营销模板。
